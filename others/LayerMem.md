# LayerMem 分层记忆：设计与实现

LayerMem 旨在给 Agent 提供基于语义-时序双轴的异质记忆结构化组织与自适应检索的长期记忆系统。


## 1. 现存问题

现有长期记忆系统存在共同的根本缺陷：

1. **仅考虑“时序”或“语义”的单一视角**，导致记忆检索时无法同时捕捉时序和语义二者信息。--- 导致一些按照时序组合的不相关的语义主题的记忆被错误合并，产生记忆碎片化和语义丢失。
2. **把所有记忆当作"同质的文本片段"处理**，忽视了不同类型记忆在语义和检索锚点上的根本差异：事件类记忆与实体交互类关系记忆被混存于同一空间，检索时无法按查询意图精准定向召回，导致相关记忆被无关条目稀释，最终喂给 LLM 的上下文质量下降。--- 导致异质记忆被混存、检索精度下降。

## 2. 设计架构

**基于语义-时序双轴模式的异质记忆组织与自适应检索。**

### 2.1 异质记忆的分类

我们观察到，记忆在**时序演化模式**上是异质的：不同类型的记忆随时间演化的方式不同，决定了它们需要不同的组织结构与召回路径。

**两种基本类型：**

| 类型 | 例子 |  检索锚点 |
|---|---|---|
| 事实记忆 Factual | "我昨天看了哪吒2" | 主题内容 |
| 关系记忆 Relational | "Alice 称赞了 Bob 的付出" | 人物关系 |

因此，两类异质记忆必须用**分别存储**，在检索时根据查询需求从对应类别的记忆库中召回，以确保最终喂给 LLM 的记忆片段**最小最精确**。

> ps. 虽然需要提取两类不同语义，但只需对原始输入流进行一次处理，即使用一个完整的 Prompt 实现双视角提取，并将提取内容分路存入 Qdrant。

### 2.2 两个维度

<u>**维度1. 语义轴（横轴）**</u>
对于语义轴，我们进行相同主题的聚类实现，由于用户的对话可能是具有跳跃性的，相同主题的内容可能并不是按顺序出现的(**Ref**. VikingMem3.1最后一段)，因此我们需要将**相同主题的内容进行聚类**，以便于在时序轴上实现压缩精炼时实现的是对同一主题内容的摘要提取。

```text
作用：决定新生成的记忆原子“归属哪个主题节点”
机制：在线增量聚类（dialogbuffer->L1写入时实时聚类，不是事后批量进行组合）

对于从 dialogbuffer 中提取出来的新记忆原子 Node
  → 计算 embedding
  → 与 L1 已有语义节点做相似度匹配
  → 归入相似度最大的节点所在的 member_ids（稳定 ID 集合）中
  → 若所有节点的相似度 < θ，则创建新语义主题集合并将该原子加入

关键设计：
  ① 用"稳定 ID + 成员集合"而非"位置区间"来描述一个语义主题集合
     → 插入新原子 O(1)，不用位置区间标识主题集合导致级联更新
  ② Factual 与 Relational 在各自独立的语义空间中进行聚类
     → 人际交互事件不会因语义相近被错误归入主题事件集合
     → 两类各自维护独立的 topic_id 空间
```

<u>**维度2. 时序轴（纵轴）**</u>
对于时序轴，我们不选择像 TiMem 那样按照 Session/Daily/Weekly...的固定时间间隔进行压缩，而是选择**在线增量压缩**，即按照同一主题集合中的原子数量进行压缩，当该集合中的原子数量达到一定阈值时，将原子压缩成一条记录，进入下一层，形成**语义时序分层压缩结构**。

```text
作用：决定记忆原子“如何随时间演化”
机制：Factual & Relational 时序分层压缩（数量驱动，在线增量） 

驱动力：数量驱动（内容自适应）而非时间驱动（日历刻度）
  → 话痨用户：压缩触发频繁，节点均匀
  → 沉默用户：慢慢积累，不进行无意义的摘要提取
  → 比 TiMem 的日历驱动更合理
  对 TiMem 的预设定时间边界实现了合理优化

Factual / Relational 路：L1-L4 分层时序摘要压缩
  → dialogbuffer → L1 → L2 → L3 → L4
  → 触发阈值：Li 中同一语义主题的 Node 数量 count >= K_count(K_count 默认是 2 且必须 >= 2，即至少两条原子才触发摘要，避免单条改写)
  → L1. 单条时间原子[多次发生的具体事件] 写入时根据语义向量在线聚簇到语义节点
  → L2. 主题摘要节点[主题级别的行为模式] 对于单条记忆的一次聚类主题摘要
  → L3. 阶段画像节点[跨时间稳定特征] 描述跨时间的稳定特性
  → L4. 稳定用户画像 构建长期较为稳定的用户个人画像
* 层级越高---时序维度-时间跨度长，越稳定；粒度维度-细节越少，抽象程度越高
* 层级越低---时序维度-越近期，越偶发；粒度维度-细节越丰富，越具体
```

**L1-L2 压缩摘要的机制(覆盖式)**：
每次将 dialogbuffer 的内容输入给 LLM 后，会提取出若干条原子记忆写入 L1。写入完成后，对本次有新增原子的每个 L1 主题集合检查触发条件：
**触发条件**：该 L1 主题集合当前节点数 >= K_count
**触发后执行**：
```text
* 输入 = 旧 L2 节点内容（若该主题对应的 L2 节点已存在）+ 本次新增的 L1 原子
       （注意：不用该集合全量 L1 原子作为输入）
* 输出 = 新 L2 节点内容，覆盖旧 L2 节点（若旧节点不存在则新建）
L1 原有节点不删除，保留用于原子记忆的检索       
```

> 不用全量 L1 原子作为输入的两个优势：
> **优势 1**：控制每次喂给 LLM 的输入长度有界，防止随历史积累出现 Lost-in-the-Middle 问题导致摘要质量下降
> **优势 2**：一定程度上减少 Token 消耗（相比全量 L1 重新摘要），因为即使是存在 Prefix-cache optimization，也是存在一定的开销的

**L1→L2 压缩执行完成后，区分两种情况**：

```text
情况 1：该 L1 主题集合已有对应的 L2 节点（非首次压缩）
  → in-place 覆盖更新该 L2 节点内容
  → 该 L2 节点所在的 L2 主题集合节点数不变

情况 2：该 L1 主题集合是首次触发压缩，尚无对应 L2 节点
  → 生成新 L2 节点，与现有 L2 主题集合做相似度匹配
  → sim >= θ_L2：insert 进已有 L2 主题集合，该集合节点数 +1
  → sim <  θ_L2：new 一个新的 L2 主题集合并 insert，节点数初始化为 1
```

**无论是情况 1 还是情况 2，执行完成后统一检查**：

```text
该 L2 节点所在的 L2 主题集合当前节点数 >= K_count
  → 触发向 L3 的压缩摘要更新
  → 递归向上，直至 L4 或不满足条件为止
```
> tips. L2-L3 和 L3-L4 的压缩摘要都是全量的，因为其大多数情况下可能是 in-place 更新，但是 in-place 所在的主题集合记忆数量 >= K_count，所以无法使用 L1-L2 的压缩逻辑。

**节点的 topic_id 标注规范**：
每个节点需标注两个 topic_id（标注在节点级别，非主题级别）：
| 字段 | 含义 | 适用层 |
|---|---|---|
| `current_topic_id` | 该节点在本层所属的主题集合 ID | L1-L4 |
| `source_topic_id` | 该节点由上一层哪个主题集合压缩得到 | L2-L4 专有 |

### 2.3 缓冲池与提取

为了更好地维护我们的记忆架构且尽量减少对于LLM的调用产生延迟&Token开销，对于新来的对话我们会选择将其放入 **dialog buffer** 中，累计达到一定的数量后再进入记忆库中。

```text
缓冲池：不断积累用户与Agent的对话消息，达到触发条件后经LLM提取写入记忆库
  → 触发条件：对话轮次达到阈值 10 或 token 数达到阈值 4096 后
  → 特点：批量处理，避免逐句调用 LLM，大幅度降低成本开销
Extraction prompt：一次 LLM 调用生成两类记忆原子
  → 双视角并行处理：需要同时包含 Factual / Relational 两类记忆类型的提取原则
  → 不过度提取：不能硬性规定两类都必须提取，需根据当前输入流自适应提取
  → 无信息量内容过滤：过滤掉无信息量内容，如"嗯""好的"、开场白等
```

### 2.4 检索

layerMem 的检索逻辑基于一个结构性观察：L1-L4 的分层压缩在**时序-语义双轴**的实现下同时编码了两个维度，即**时序稳定性与语义抽象度**，且两个维度在 embedding 空间里天然对齐：
```text
L1：具体事件，偶发，embedding 偏具体
L2：主题摘要，反复出现，embedding 偏模式
L3：稳定特征，跨时间，embedding 偏抽象
L4：综合画像，全局，embedding 最抽象

查询文本的 embedding 也落在这个具体→抽象的维度上：
  "用户上周做了什么" → 偏具体 → 自然靠近 L1
  "用户喜欢什么风格" → 偏抽象 → 自然靠近 L3
```
基于这一结构性观察，我们设计由**检索规划器**显示决策召回哪些层：具体查询倾向 L1，抽象查询倾向 L2-L4，而非依赖 ANN 自动对齐（后者可以作为待验证假设留作消融实验）。


```text
查询
  ↓
检索规划器（一次 LLM 调用）
  输出：
    tracks:         ["factual" | "relational"]            // relational 是可选项
    keywords:       ["关键词1", ...]                       // BM25 用，3-6个
    factual_layers: ["L1"] | ["L2-L4"] | ["L1","L2-L4"]   // 根据查询粒度需求判断
  ↓
按轨道并行分流：

  ── Factual 轨 ──────────────────────────────
    按检索规划器生成的 layers 字段决定参与召回的层范围（L1 / L2-L4 / 全层）
    在指定层范围内 Hybrid 召回（ANN + BM25），宽泛召回候选集，不考虑层次/主题，
    相似度阈值过滤（score < θ 的条目直接丢弃）
    剩余条目取 top-K（K 是上限，不是目标），提前过滤是为了不用为了选 topk 而引入非相关记忆
    → 简单单跳查询：阈值过滤后可能只剩 1-2 条，直接返回
    → 复杂多跳查询：阈值过滤后剩余较多，再截断到 K
    
  ── Relational 轨（如需）──────────────────────────
    同 Factual 轨，流程完全一致
    → top-k
  ↓
多轨合并（如多触发轨）：
    Factual top-K + Relational top-K
      → RRF 重排序（消除两轨分数量纲差异）
      → 取合并后 top-K
    State 结果直接附加到末尾，不参与重排
  ↓
将所有记忆条目输入至LLM，生成最终答案
```

> <u>**与 TiMem 的区别**</u>：TiMem 以查询难度（simple/hybrid/complex）决定召回层组合，LayerMem 以查询的**内容粒度需求**（需要原子事件 / 摘要画像 / 两者）决定 factual_layers——两者并不等价（一个“简单”的查询可能恰好需要 L3-L4 的稳定画像）。同时以数据驱动的相似度阈值过滤控制召回数量，避免固定 top-K 引入低相关记忆。
